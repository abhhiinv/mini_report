Abstract
Network security has become increasingly critical as modern cyberattacks grow in frequency,
stealth, and complexity, threatening organizational digital infrastructure across all sectors.
Traditional signature-based intrusion detection systems struggle to detect novel zero-day
exploits, evasive low-rate probing, and evolving volumetric attack vectors. Machine learning
offers a promising paradigm for adaptive anomaly detection, yet operational implementations
frequently encounter significant challenges, including severe class imbalance between benign
and malicious flows, prohibitive inference latency, and the absence of end-to-end integration
between theoretical offline models and live packet capture pipelines.
This work presents the Real-Time Network Intrusion Detection and Alert System (NIDAS),
an end-to-end machine learning platform engineered for continuous network monitoring and
automated threat alerting. The system is trained and evaluated on a curated corpus of 1,799,905
network flows derived from the CIC-IDS2017 benchmark, covering Normal Traffic alongside
four prevalent attack vectors: Denial of Service (DoS), Distributed Denial of Service (DDoS),
Port Scanning, and Brute Force. A rigorous five-stage feature selection methodology, comprising
zero-variance removal, collinearity reduction (r > 0.90), Kruskal-Wallis non-parametric
significance testing, Random Forest feature importance scoring, and domain validation, prunes
77 raw flow features down to an optimal 40-feature operational space.
To overcome the operational limitations of single-model classifiers, NIDAS employs a soft-voting
ensemble coupling Random Forest and Extreme Gradient Boosting (XGBoost). Random Forest
(B = 200 trees) provides variance dampening across noisy packet metrics, while XGBoost (300
estimators with histogram-based binning) supplies precise bias reduction for difficult boundary
distinctions. Balanced sample weighting counters class imbalance without introducing synthetic
oversampling artifacts. On an independent test set of 394,168 flows, the ensemble achieves
99.88% overall accuracy, a macro-averaged F1-score of 99.76%, and sub-millisecond per-flow
inference latency (< 0.6 ms).
The operational pipeline is deployed as a lightweight client-server application featuring
asynchronous live packet capture via Npcap/libpcap, online feature extraction using Welford’s
algorithm, and a stateful cross-flow sliding window detector for stealthy port scans. Inferred
threats are categorized into color-coded severity tiers (Critical, High, Medium) and streamed
via FastAPI WebSockets to an interactive React SOC dashboard with automated self-traffic
suppression. The result is a robust, production-ready solution that bridges theoretical intrusion
detection with low-overhead, real-time security operations.

Introduction

The rapid expansion of digital infrastructure has made computer networks a primary target
for malicious actors. Global cybercrime damages are projected to exceed ten trillion dollars
annually in 2025–2026, with India seeing sharp rises in DDoS and ransomware attacks targeting
banking, healthcare, and government networks.
An Intrusion Detection System (IDS) monitors network traffic for unauthorized access or
malicious behaviour. Signature-based systems match traffic against known attack patterns;
anomaly-based systems flag deviations from a learned baseline. Signature-based approaches fail
against zero-day exploits, driving research into ML-based detection capable of generalizing to
unseen attacks.
A persistent gap exists between academic IDS research and practical deployment. Most published
systems evaluate on static datasets without addressing real-time operational pipelines, continuous
alerting, or analyst-facing interfaces, limiting operational value. A further challenge is severe
class imbalance: benign flows dominate real traffic, and models that ignore this risk high
false-negative rates on minority attack classes.
This project is motivated by CERT-In mandates for faster incident detection and the expanded
network perimeter from hybrid cloud and remote work environments.
Objectives:
1. Train a Random Forest + XGBoost ensemble on the combined CIC-IDS2017 and
CSE-CIC-IDS2018 benchmark for multi-class intrusion detection.
2. Implement a real-time alert mechanism upon detection of anomalous flows.
3. Build a real-time detection pipeline: live flow feature extraction → ensemble classification
→ alerting and telemetry.
4. Comparatively evaluate RF, XGBoost, and the ensemble on accuracy, precision, recall,
and F1.
NIDAS is designed as an end-to-end real-time intrusion detection pipeline that processes network
traffic via a custom CICFlowMeter implementation. Each flow is classified into: Normal Traffic,
DoS, DDoS, Port Scanning, or Brute Force. Detected anomalies trigger timestamped alerts
with predicted attack type and confidence score. A React JS dashboard surfaces live flow
classifications; a FastAPI backend handles communication between the detection engine and UI.
The key contribution is end-to-end integration of ensemble detection with real-time alerting and
dashboard visualization operationally actionable, not just accurate.

PAPER I
Ness S, Eswarakrishnan V, Sridharan H, Shinde V, Janapareddy N V P, & Dhanawat V. (2025).
Anomaly detection in network traffic using advanced machine learning techniques. IEEE Access,
vol. 13, pp. 16133–16149.
This paper investigates various machine learning models for detecting anomalies in network
traffic, focusing on overcoming challenges like class imbalance and feature complexity. Accurate
anomaly detection serves as a proactive measure to safeguard network integrity and identify
dynamic security risks.
The authors utilize five machine learning algorithms: Isolation Forest, Naive Bayes, XGBoost,
LightGBM, and Support Vector Machine (SVM). The study relies on the KDDCup’99 dataset,
which includes normal activity and multiple attack types like DoS, Probe, Remote to Local (R2L),
and User to Root (U2R). Data preprocessing involves the Synthetic Minority Over-sampling
Technique (SMOTE) for balancing classes, label encoding for categorical features, and Principal
Component Analysis (PCA) for feature extraction and dimensionality reduction.
The models were evaluated using 5-fold cross-validation with metrics including accuracy,
precision, recall, and F1-score. LightGBM achieved the highest test accuracy (1.0) and F1-score
(0.85). SVM also demonstrated strong performance with a test accuracy of 0.85 and F1-score of
0.86. Conversely, Isolation Forest performed poorly with a test accuracy of 0.40, struggling with
the dataset’s complexity.
The study concludes that advanced ensemble and gradient boosting methods like LightGBM
and XGBoost, alongside SVM, offer robust detection capabilities for network traffic anomalies.
Future work suggests integrating deep learning techniques like CNNs and RNNs, using ensemble
methods to reduce false positives, and applying models to newer datasets like CICIDS and
NSL-KDD.

Title

Anomaly Detection in Network Traffic Using Advanced Machine
Learning Techniques

Area of Work

Evaluating and optimizing supervised and unsupervised ML models
to detect anomalies in network traffic, addressing data imbalance and
feature complexity.

Dataset

KDDCup’99 dataset containing normal traffic and multiple attack types
(DoS, Probe, R2L, U2R). Balanced using SMOTE.

Methodology

Data preprocessing with missing value handling, label encoding, z-score
normalization, and PCA. Five ML models trained with hyperparameter
tuning and 5-fold cross-validation (80:20 split).

Algorithm

Isolation Forest, Naive Bayes, XGBoost, LightGBM, Support Vector
Machine (SVM).

Result/Precision

LightGBM: Test Accuracy = 1.0, F1 = 0.85. SVM: Accuracy = 0.85,
F1 = 0.86. XGBoost: Accuracy = 0.83, F1 = 0.84. Isolation Forest:
Accuracy = 0.40.

Advantages

Comprehensive comparison of classical ML models. Highlights efficacy
of gradient boosting and effectively uses SMOTE and PCA.

Future Proposal

Recommends deep learning (CNNs, RNNs), ensemble methods to
reduce false positives, unsupervised approaches for zero-day attacks,
and validation on CICIDS and NSL-KDD datasets.

PAPER II
Fathima AHN, Ibrahim SPS, Khraisat A. Enhancing Network Traffic Anomaly Detection:
Leveraging Temporal Correlation Index in a Hybrid Framework. IEEE Access. 2024 Sep
11;12:136805–136824.
This paper introduces the Temporal Metric-Driven GRU Embedded Generative Neural Network
(TMG-GRU-VAE) to improve the identification of network traffic irregularities. Traditional
models often emphasize detecting network attacks but struggle to capture the dynamic and
temporal aspects of network traffic, making it difficult to detect subtle behavioral shifts.
The proposed methodology combines Gated Recurrent Units (GRU) with Variational
Autoencoders (VAE) to effectively learn normal temporal patterns in sequence data. Additionally,
the authors propose a novel Temporal Correlation Index (TCI) score to assess temporal behavior
and establish dynamic anomaly detection thresholds. The study utilizes the CIC-IDS-2017
and CIC-IDS-2018 datasets, splitting the preprocessed data into 70% training and 30% testing
subsets.
The models were evaluated using accuracy, precision, recall, F1-score, and false alarm rates. The
TMG-GRU-VAE model combined with TCI achieved significant reductions in False Positives.
Improvements in FP reduction ranged from 7.2% to 12.9% for CIC-IDS-2017, and 7.1% to
14.1% for CIC-IDS-2018. The GRU-VAE with TCI achieved the highest True Positive rates and
the lowest FP rates.
The research demonstrates that integrating temporal correlation metrics with hybrid deep learning
frameworks substantially reduces false alarms and improves overall anomaly detection accuracy.
Future work aims to develop explainable AI models to enhance interpretability and confidence
in detection results, particularly for addressing zero-day threats.

changes over time.

resilience.

PAPER III
Ji C, Liu H, Dai W. Hybrid Model for Network Traffic Anomaly Detection Based on Parallel
Two-Stage Feature Fusion. IEEE Access. 2025 Feb 4;13:27310–27324.
The paper proposes GRU-ResCBANet, a deep learning hybrid model tailored for network traffic
anomaly detection. The model addresses issues such as low detection rates for minority attack
classes and high false alarm rates by employing a parallel two-stage feature extraction and fusion
technique.
In the first stage, the ResCBANet module uses an improved residual network enhanced with a
Convolutional Block Attention Module (CBAM) to extract spatial features and channel attention.
In parallel, a Gated Recurrent Unit (GRU) module captures temporal dependencies. These
features are fused and passed to a fully connected classification layer using a Softmax activation
function. The model was evaluated on the NSL-KDD, UNSW-NB15, and CICIDS2017 datasets,
which were preprocessed and reduced in dimensionality using ANOVA for feature selection.
GRU-ResCBANet delivered state-of-the-art results. For binary classification, it achieved
accuracies of 99.70% on NSL-KDD, 99.16% on UNSW-NB15, and 99.83% on CICIDS2017.
For multi-class classification, accuracies reached 99.69%, 98.23%, and 99.79% respectively. The
model consistently outperformed eight other comparison models, including SVM, RF, 2D-CNN,
and CNN-LSTM.
The study concludes that parallel integration of GRU and ResCBANet successfully
captures comprehensive feature representations, significantly boosting anomaly detection
accuracy. Future directions include exploring model compression for edge computing,
applying oversampling strategies for class imbalance, and integrating federated learning for
privacy-preserving distributed security.

Title

Hybrid Model for Network Traffic Anomaly Detection Based on Parallel
Two-Stage Feature Fusion

Area of Work

Improving network traffic anomaly detection accuracy and reducing
false alarm rates using a hybrid deep learning model that fuses
spatiotemporal and channel features.

Dataset

NSL-KDD, UNSW-NB15, and CICIDS2017 datasets. Transformed
into 3D structured inputs after dimensionality reduction via ANOVA.

Methodology

Parallel two-stage architecture. Stage one uses ResCBANet (CNN +
Residual Units + CBAM) for spatial/channel features. Stage two uses
GRUs for temporal features. Outputs fused and classified using a fully
connected Softmax layer.

Algorithm

GRU-ResCBANet, Residual Convolutional Block Attention Network
(ResCBANet), Gated Recurrent Units (GRU).

Result/Precision

Binary classification: 99.70% (NSL-KDD), 99.16% (UNSW-NB15),
99.83% (CICIDS2017). Multi-class: 99.69%, 98.23%, 99.79%
respectively. Highest F1-scores among 8 baseline models.

Advantages

Parallel two-stage strategy efficiently leverages multidimensional traffic
characteristics. Excels in detecting both frequent and complex attack
types with high stability.

Future Proposal

Model pruning/quantization for edge devices, oversampling
for UNSW-NB15 class imbalance, and federated learning for
privacy-preserving distributed security.

Findings and Proposals

Findings
The reviewed literature establishes several consistent findings. Ensemble and fusion-based
approaches uniformly outperform single-model classifiers in network traffic anomaly detection,
across both traditional ML and deep learning paradigms. The CIC-IDS2017 dataset is the
dominant benchmark in current IDS research and is the standard against which results from this
project are comparable. Temporal features, particularly IAT-based features, carry significant
discriminative information that improves detection of attack types with characteristic timing
signatures. Despite the progress in detection accuracy, none of the three reviewed papers
implement a real-time operational pipeline; all evaluate models in an offline, batch mode.
Identified Gap
The common gap across all three reviewed papers is the absence of a real-time alert mechanism.
Each paper treats intrusion detection as a classification task on a static dataset, with no
consideration of how detected anomalies are surfaced to an operator as they occur. This
gap is practically significant: a model with high batch accuracy that cannot generate timely
alerts provides no operational advantage over a post-hoc log analysis.
Proposal
This project proposes to close this gap by integrating a real-time alerting mechanism directly into
the ensemble detection pipeline. The proposed system extends the soft-voting RF + XGBoost
ensemble validated by Ness et al. with a FastAPI backend that classifies incoming flows in real
time and triggers alert notifications upon detection of anomalous traffic. A React JS dashboard
surfaces these alerts to the operator with predicted attack category and ensemble confidence
score. This integration of detection and alerting constitutes the novel contribution of this project
over the reviewed literature.

3.1.1

About the Dataset

To establish a resilient intrusion detection system capable of mitigating domain-specific
vulnerabilities, this project integrates two widely recognized benchmark datasets developed by
the Canadian Institute for Cybersecurity: CIC-IDS2017 and CSE-CIC-IDS2018. Both datasets
simulate realistic enterprise network traffic containing diverse, state-of-the-art attack executions
alongside normal background user activity, captured using the network traffic profiling tool
CICFlowMeter.
The CIC-IDS2017 benchmark comprises eight raw CSV captures totaling 2,830,743 network
flow records across 79 columns. The CSE-CIC-IDS2018 benchmark, collected in a collaborative
effort between the Communications Security Establishment (CSE) and the Canadian Institute
for Cybersecurity (CIC) on AWS infrastructure, encompasses six targeted attack captures
used in this study (BruteForce, BruteForce2, BruteForceSSH, DDoS, DoS, and DoS2) totaling
6,291,449 raw flow records across 80 columns. To harmonize the two heterogeneous schemas,
abbreviated column headers in the 2018 dataset (e.g., Dst Port, Tot Fwd Pkts, Pkt Len Mean)
were systematically mapped to the standardized naming conventions of CIC-IDS2017. Internal
repeated header lines and non-flow metadata attributes (Protocol and Timestamp) were excluded,
yielding a combined pre-cleaning corpus of 9,117,071 flow records across 77 shared numeric
features.
The raw multiclass labels across both datasets were consolidated into five harmonized traffic
categories:
• Normal Traffic: Merging BENIGN from CIC-IDS2017 and benign from
CSE-CIC-IDS2018.
• Denial of Service (DoS): Aggregating DoS Hulk, DoS GoldenEye, DoS slowloris, and
DoS Slowhttptest from 2017 with dos attacks-goldeneye, dos attacks-slowloris, dos
attacks-hulk, and dos attacks-slowhttptest from 2018.
• Distributed Denial of Service (DDoS): Combining DDoS from 2017 with ddos
attacks-loic-http, ddos attack-loic-udp, and ddos attack-hoic from 2018.
• Brute Force: Unifying credential-guessing attacks including FTP-Patator and
SSH-Patator from 2017 with ftp-bruteforce and ssh-bruteforce from 2018.
• Port Scan: Incorporating port scanning probe activity (PortScan from 2017).

Data Preprocessing

To transform the 9.12 million raw flow observations into an optimal, high-fidelity training

3.2.1

Data Cleaning

A systematic five-stage data cleaning and preparation pipeline was applied to ensure dataset
integrity and remove non-informative features:
1. Zero-Variance Column Removal: The 8 constant columns identified during exploration
were dropped, retaining 69 informative numeric features.
2. Infinity and Null Value Cleaning: All infinite values (±∞) were converted to NaN, and
the 26,026 affected rows were eliminated, leaving 9,091,045 clean records.
3. Deduplication: Exact duplicate rows across the feature space were purged, eliminating
2,263,887 records and yielding 6,827,158 unique flow records.
4. Benign Subsampling and Class Balancing: In the unique corpus, Normal Traffic
accounted for over 5.91 million records (86.6%). Retaining all benign records would
induce severe majority-class bias and excessive training overhead without adding
behavioral variance. Consequently, Normal Traffic was randomly subsampled at 15%
(887,162 records) and combined with 100% of all attack records (912,743 flows). This
produced a balanced, highly representative dataset of 1,799,905 records composed of:
• Normal Traffic: 887,162 records (49.29%)
• DoS: 390,200 records (21.68%)
• DDoS: 328,605 records (18.26%)
• Brute Force: 103,244 records (5.74%)
• Port Scan: 90,694 records (5.04%)
In terms of dataset origin, CSE-CIC-IDS2018 contributed 1,064,113 flows (59.12%) and
CIC-IDS2017 contributed 735,792 flows (40.88%), ensuring robust cross-environment
representation.
5. Categorical Label Encoding: The target categorical variable (Attack Type) was
mapped to integers using scikit-learn’s LabelEncoder, assigning integer indices 0 to
4 corresponding to Brute Force, DDoS, DoS, Normal Traffic, and Port Scan.

Packet length features capture the size characteristics of packets in both forward (client-to-server)
and backward (server-to-client) directions, including maximum, minimum, mean, and standard

discriminative features, with Bwd Packet Length Mean, Packet Length Std, Bwd Packet Length

Inter-Arrival Time (IAT) features measure the time intervals between successive packets within a
flow, computed separately for the overall flow, the forward sub-flow, and the backward sub-flow.
Standard deviation, maximum, and minimum IAT values are included. As demonstrated by
Fathima et al. (2024), temporal features of this nature carry significant discriminative information
for attacks that exhibit periodic or bursty timing patterns.
Traffic volume features include Total Length of Fwd Packets, Total Fwd Packets, and Total
Backward Packets, characterizing the overall data volume transferred in each direction. These
complement packet length features for detecting volume-based attacks.
Flow-level throughput features include Flow Bytes/s, Flow Packets/s, and Bwd Packets/s, which
characterize the volumetric rate of the flow.
TCP flag features record the presence of FIN, PSH, and ACK flags within the flow. These help
distinguish connection setup and teardown patterns associated with specific attack types such as
port scans.
TCP window and header features include the initial TCP window sizes in both directions,
forward and backward header lengths, and minimum segment size, which reflect protocol-level
behaviour that varies across attack types.
Active and Idle time features capture the periods of activity and inactivity within a flow. Active
Max and Idle Mean are retained after feature selection.

3.4

Analysis of Architecture and Algorithms

The Real-Time Network Intrusion Detection and Alert System (NIDAS) employs a hybrid
ensemble learning architecture designed to deliver high-throughput, low-latency threat detection
across live network traffic. Structured network telemetry is characterized by extreme
non-linearities, heavy-tailed burst distributions, and severe class imbalances between benign
and malicious flows. Single-model classifiers frequently suffer from an operational trade-off:
high-variance models overfit to benign network fluctuations, generating excessive false alarms,
whereas high-bias models fail to capture stealthy, low-volume intrusions. To overcome these
limitations, NIDAS couples Random Forest and Extreme Gradient Boosting (XGBoost) within
a soft-voting ensemble framework, combining the variance-reduction strengths of bagging with
the bias-reduction precision of gradient boosting. The following sections provide an in-depth
analysis of the mathematical foundations, operational strengths, inherent weaknesses, and

project-specific scope of each proposed algorithm.
3.4.1

Detailed Study Report of the Proposed Algorithms

Random Forest
Random Forest is a non-parametric ensemble learning method based on bootstrap aggregating
(bagging) of unpruned or depth-constrained decision trees. During training, the algorithm
constructs B = 200 individual classification trees using bootstrap samples drawn with
replacement from the 1.58 million training flows. At each node split, instead of evaluating
all candidate dimensions across the feature space, a random subset of size m = 0.4 × 40 = 16
features is sampled. Splitting criteria evaluate impurity reduction (such as Gini impurity, defined
as Gini(p) = 1 − ∑Cc=1 p2c ) to recursively partition the high-dimensional flow metric space.
The final prediction for an input flow vector x is formed by aggregating posterior probability
distributions across all individual trees:
PRF (y = c | x) =

1 B
∑ Pb(y = c | x)
B b=1

(3.1)

This dual randomization protocol (subsampling training instances and subsampling candidate
features) effectively decorrelates individual decision trees, substantially lowering the overall
variance of the ensemble without elevating its bias. Restricting the maximum tree depth to 10
(max_depth = 10) prevents individual estimators from overfitting to transient network artifacts
or memorizing specific port signatures.
Strengths: Exceptional resistance to overfitting on high-dimensional tabular data through
variance dampening; native resilience to noisy, skewed, or collinear network traffic features
without requiring strict Gaussian assumptions; invariance to monotonic feature transformations,
ensuring stable decision thresholds across metrics spanning several orders of magnitude;
transparent model interpretability via Mean Decrease in Impurity (MDI) feature importance
rankings; and high computational parallelization during training across all available CPU cores
(n_ jobs = −1).
Weaknesses: Significant memory footprint during deployment because the complete structure of
200 multi-class decision trees must reside concurrently in RAM; inference latency scales
directly with tree count and depth, presenting potential computational overhead during
extreme packet floods compared to compact linear models; inability to extrapolate beyond
the numerical boundaries observed during training; tendency to favor majority traffic classes if
class imbalances are unweighted; and redundant tree node partitions when processing correlated
flow characteristics.

1. Data Acquisition: The system integrates 9,117,071 raw flow records from the CIC-IDS2017
and CSE-CIC-IDS2018 benchmarks, capturing 77 initial numeric flow characteristics and
target metadata. After deduplication, cleaning, and subsampling, a curated benchmark of

robust multi-environment representation. In deployment, a custom Python CICFlowMeter
engine captures live packets from network sockets/PCAP and extracts the identical 40
bidirectional flow features in real time.
2. Data Preprocessing and Preparation: The raw corpus undergoes zero-variance removal
(dropping 8 constant features, reducing 77 to 69 dimensions), conversion of ±∞ values to NaN
and dropping of 26,026 corrupted rows, and deduplication of 2,263,887 duplicate records.
Labels are harmonized into five core classes (Normal Traffic, DoS, DDoS, Brute Force, and
Port Scan) while peripheral attack classes are excluded. Benign records are subsampled
at 15% (887,162 flows) and merged with 100% of attack records. A four-stage feature
refinement process (69 → 53 → 52 → 46 → 40) eliminates collinear and domain-sensitive
features. Categorical labels are encoded using LabelEncoder (0–4), inputs are normalized
using RobustScaler fitted exclusively on the training split, and discriminative feature weights
(3.0×, 2.0×, 1.0×) and balanced sample weights are computed.
3. Train / Model Building (Ensemble): An 80% stratified training partition (≈ 1.58 million
flows) is used to train the base estimators. Random Forest (200 trees, max_depth=10,
max_features=0.4) and XGBoost (300 estimators, max_depth=6, learning_rate=0.1, GPU
histogram method) are fitted independently using the precomputed balanced sample weights
on the weighted feature space. The soft-voting ensemble is constructed by combining the
pre-fitted estimators to compute probability averages across both models. Serialized model
artifacts (ensemble_model.pkl, scaler.pkl, label_encoder.pkl, and feature_weights.pkl) are
generated.
4. Model Evaluation and Comparison: The trained ensemble is evaluated on the held-out

(0.9994), per-class Precision, Recall, and F1-scores, as well as operational False Positive
Rates (0.021% on benign traffic) and False Negative Rates. Standalone Random Forest and
XGBoost baselines are benchmarked against the soft-voting ensemble.

erratic, high-confidence misclassifications.

an essential regularizing counterweight. In operational network security, the primary operational
bottleneck is not marginal offline accuracy, but alert fatigue induced by false alarms on legitimate
background traffic. When high-volume benign traffic encounters the detector, isolated statistical
spikes can cause a single classifier to output overconfident threat classifications. Under the
soft-voting scheme, an alarm is triggered only when supported by continuous probabilistic

0.021%, ensuring that security operators can trust alerts without being overwhelmed by false
alarms.
Furthermore, soft probability averaging generates smoothly distributed confidence vectors
across all five traffic classes rather than polarized, brittle binary outputs. In the production
deployment of NIDAS, these calibrated confidence scores directly feed the alerting engine,
allowing the system to differentiate between unambiguous high-volume intrusions (such
as volumetric DDoS and DoS floods) and ambiguous low-rate anomalies (such as stealthy
port scans). High-confidence detections trigger immediate high-priority terminal alerts and
automated log dispatches, whereas borderline predictions are flagged for secondary inspection.
This multi-tiered operational triage is uniquely enabled by the ensemble’s balanced posterior
probabilities, validating its selection over a standalone classifier despite the negligible 0.01%
difference in benchmark accuracy.

The empirical evaluation validates the primary research hypothesis: a soft-voting ensemble
combining Random Forest and XGBoost, trained with discriminative feature weighting, balanced
sample weights, and RobustScaler normalization, delivers near-perfect classification across
diverse attack families. The resulting 99.94% accuracy and 0.9994 macro F1 outperform

The key strength of the proposed system lies in its balanced sensitivity: minority attack classes
such as Brute Force and Port Scan achieve F1-scores of 0.9997 and 0.9992 respectively,
directly validating the combination of balanced sample weighting and discriminative feature
weighting (scaling high-importance features by 3.0× and medium-importance features by 2.0×).

distorted by outlier values.

network interface buffering could impact classification confidence, which is mitigated in NIDAS

Model Deployment

The trained ensemble is deployed as an end-to-end real-time intrusion detection and alerting
system. The operational architecture integrates four serialized model artifacts with an
autonomous wire-level flow reassembly engine and dual telemetry interfaces for console and
web-based monitoring.

6.1

Model Implementation

Network packets captured at the socket or network interface card (NIC) layer arrive as discrete,
unorganized frames. To transform raw packet streams into the structured 40-dimensional
feature vectors expected by the ensemble, a custom, lightweight Python reimplementation of
CICFlowMeter was engineered into the pipeline.
The flow generator tracks active communication sessions using a bidirectional 5-tuple hash key
comprising:
Flow Key = (Source IP, Destination IP, Source Port, Destination Port, Protocol)

(6.1)

When a packet is intercepted, the engine checks whether its forward or reverse 5-tuple already
exists in an active flow cache. If the reverse key exists, the packet is flagged as a backward
(server-to-client) transmission; otherwise, a new flow record is instantiated with the packet
designated as forward (client-to-server).
To maintain constant memory bounds during high-throughput network monitoring, the flow
engine manages active sessions through dual expiration timers:
1. Idle Timeout (Tidle = 5 s): If no packets are observed across a flow for five consecutive
seconds, the connection is deemed terminated (or abandoned), triggered for feature
finalization, and dispatched to the inference queue.
2. Active Timeout (Tactive = 120 s): Sustained connections that transmit packets
continuously without idle gaps (such as large file transfers or volumetric DoS/DDoS
flooding) are forcibly flushed every 120 seconds. This prevents long-lived flows from
delaying attack detection and eliminates unbounded cache memory growth.
Buffering thousands of individual packet payloads to compute statistical properties (such as
mean and variance of packet lengths and inter-arrival times) is computationally prohibitive at line
rate. To achieve sub-millisecond execution with a memory footprint under 45 MB, the custom
flow generator implements Welford’s algorithm for numerically stable, single-pass computation
of running statistics.

Upon flow termination, the finalized record is handed over to the Python inference pipeline. The
execution sequence follows five deterministic stages:
1. Feature Ordering and Alignment: The 40 extracted metrics are mapped into the exact
sequential feature ordering established during offline model training.
2. Sanitization and Standardization: Infinite values (±∞) resulting from zero-duration
divisions are replaced with NaN and handled. The pre-fitted RobustScaler standardizes
the numeric vector, followed by multiplication by the discriminative feature weight vector
(3.0× on primary flow dynamics, 2.0× on medium-importance features).
3. Dual-Model Consensus Inference: The standardized vector is evaluated by both
Random Forest and XGBoost base estimators, generating continuous posterior probability
distributions across the five classes. Soft probability averaging computes the consensus
confidence vector.
4. Threat Severity Assignment: If the argmax prediction corresponds to an anomaly, a
threat record is generated assigning a calibrated severity rating (Critical for DDoS and
DoS, High for Brute Force, Medium for Port Scan).
5. Audit Logging and Telemetry Dispatch: Telemetry containing timestamps, socket
addresses, predicted classifications, model votes, and confidence scores is appended to
alert_log.csv for forensic auditability, while simultaneously streaming to the terminal CLI
and web dashboard.
Deploying the inference pipeline on live network interfaces revealed several operational
considerations that do not arise during offline dataset processing. Specific engineering
adjustments were implemented to ensure system responsiveness and prevent false alarms:
1. Flow Inactivity Timeout Tuning: In live network environments, persistent TCP
Department of Computer Applications, MACE

54

Real-Time Network Intrusion Detection and Alert System

connections (such as HTTP keep-alive channels) often experience long idle gaps. Under
default CICFlowMeter settings with a 120-second inactivity timeout and a 10-second
sweep interval, completed flow records remained buffered in memory for up to 130 seconds
before being finalized and displayed. By reducing the flow timeout to 30 seconds and
the cleanup sweep interval to 5 seconds, worst-case latency for emitting completed flows
dropped from approximately 130 seconds to 35 seconds without prematurely truncating
active sessions.
2. Single-Threaded Estimator Locking: Scapy executes its packet sniffing loop on a
dedicated thread while passing completed flows to the prediction pipeline. By default, both
Random Forest and XGBoost attempt to utilize all CPU cores via joblib multiprocessing.
In a live capture loop, spawning sub-processes across threads introduced thread-local lock
contention and system warnings. Setting the estimator thread count to single-threaded
mode across all sub-trees eliminated concurrency overhead and stabilized real-time
execution.
3. Internal Traffic Pre-Filtering: Local network adapters regularly exchange operational
frames such as IPv6 link-local messages, multicast DNS (mDNS), and address
autoconfiguration packets. Because benchmark training datasets consist solely of routable
host-to-host communications, evaluating these local infrastructure frames with machine
learning models led to false positives (such as mDNS multicasts incorrectly flagged as
Brute Force). A pre-prediction filter screens out loopback, link-local, multicast, and
broadcast addresses before inference, allowing only routable unicast traffic to reach the
classifier.
4. Dashboard Self-Traffic Exclusion: The web user interface communicates with the
FastAPI server over port 8000 using HTTP and WebSockets. To prevent feedback loops
where dashboard communications generate captured packets that re-enter the feature
extractor, all packets on destination or source port 8000 are automatically bypassed from
flow tracking and alerting.

8.

Conclusions

This project presented the design, implementation, and empirical evaluation of the Network
Intrusion Detection and Alert System (NIDAS), an end-to-end framework capable of capturing,
analyzing, and detecting network-level intrusions in real time. Rather than relying solely on
sanitized benchmark performance, the system was validated across both offline benchmarks
and live network captures, providing critical engineering insights into the realities of deploying
machine learning in operational cybersecurity environments.

8.1

Implementation of the Real-Time IDS Pipeline

NIDAS successfully established a complete, standalone network monitoring pipeline that spans
all layers from wire-level packet capture to automated incident notification:
• Autonomous Flow Generation: A custom, lightweight Python reimplementation of
CICFlowMeter was developed to perform real-time packet sniffing, bidirectional flow tracking,
and dynamic computation of 40 flow-level features, bypassing the latency and external
dependencies of legacy Java utilities.
• Ensemble Classification Engine: A soft-voting ensemble combining Random Forest and
XGBoost was trained on the combined CIC-IDS2017 and CSE-CIC-IDS2018 benchmark
corpus (1, 799, 905 flows). By uniting the variance-reduction strengths of bagging with the
gradient-guided optimization of boosting, the ensemble achieved an offline test accuracy
of 99.94% and a macro-averaged F1-score of 0.9994 across five distinct traffic categories:
Normal Traffic, DoS, DDoS, Brute Force, and Port Scan.
• Operational Telemetry and Alerting: An automated threat-mapping engine parses ensemble
confidence vectors, assigns attack severity levels (Critical, High, Medium), logs persistent
incident telemetry to alert_log.csv, and renders real-time color-coded alerts on both the
terminal interface and the full-stack web dashboard.

8.2

Pipeline Integrity and Training Inference Parity

A critical empirical lesson uncovered during practical deployment was the strict necessity
of end-to-end transformation symmetry between offline training and live inference. In early
deployment iterations, a feature transformation discrepancy was identified where discriminative
feature weighting (3.0× for high-importance flow dynamics and 2.0× for medium-importance
attributes) was applied during estimator training but omitted in the live inference preprocessing
step.
This discrepancy caused significant confidence skew on boundary attack signatures; specifically,
probe and port-scanning vectors exhibited severely degraded classification confidence (collapsing
Department of Computer Applications, MACE

59

Real-Time Network Intrusion Detection and Alert System
to borderline probabilities of ∼ 4%). Rectifying this pipeline bug by ensuring exact symmetry in
RobustScaler standardization and weight multiplication immediately restored high-confidence
detection (75%-96%) across live network flows. This underscored that high theoretical model
accuracy remains fragile unless absolute parity is enforced between training-time and runtime
feature engineering pipelines.

8.3

Domain Generalization and Continuous Adaptation

Evaluating the trained model on live network environments revealed a pronounced generalization
gap between static academic benchmarks and modern operational attack tools:
• TCP Stack and Tool Evolution: Benchmark datasets recorded in simulated testbed
environments capture tool behaviors and operating system TCP stacks specific to their
recording era. When modern attack utilities (such as Go-based HTTP flooding scripts or
updated Hydra brute-force engines) are executed against contemporary operating systems,
deviations in TCP window negotiation, inter-arrival timing, and header lengths cause pure
benchmark-trained models to struggle.
• Syntactic Artifacts vs. Behavioral Signatures: In real-time testing, the baseline model
initially exhibited confusion between scanning probes and brute-force attempts because
fixed tool payloads (such as Hydra’s 56-byte FTP commands versus Nmap’s 52-byte probe
packets) occupied adjacent feature spaces. By capturing local traffic profiles, applying
targeted labeling, and retraining the ensemble on localized behavioral patterns, the model
successfully transitioned from memorizing tool-specific payload artifacts to recognizing
generalized behavioral signatures (flow duration patterns, packet burst rates, and connection
symmetries). This demonstrated that continuous learning and localized retraining loops are
indispensable for real-world intrusion detection systems.

8.4

Critical Analysis of Operational Limitations

While the ensemble attained exceptional performance on the curated test set (surpassing 99.9%
accuracy with an FPR of 0.021% on benign traffic), real-world deployment exposed critical,
predictable edge cases inherent to flow-based tabular architectures:
• The Single-Packet / Zero-Duration Trap (UDP Noise): The 40 flow-level tabular features
do not encode transport-layer protocol semantics (TCP versus UDP). Consequently, legitimate
single-packet UDP interactions (such as Network Time Protocol (NTP) clock synchronizations
characterized by 1 forward packet, 0 backward packets, and 0 duration) produce flow vectors
statistically indistinguishable from single-probe reconnaissance scans. This occasionally
triggered false-positive Port Scan alerts on benign background NTP traffic, demonstrating that
Department of Computer Applications, MACE

60

Real-Time Network Intrusion Detection and Alert System

purely statistical flow models require complementary protocol-aware whitelisting or cross-flow
correlation.
• The Temporal Trap (Slow Benign Transactions): Tree-based models heavily exploit Flow
Duration to isolate sustained denial-of-service flooding. However, benign connections with
long idle delays or slow server response times (such as slow HTTP/HTTPS transactions
spanning 40 to 60 seconds with minimal packet volume) can mimic the temporal profile of
low-and-slow DoS attacks (e.g., Slowloris or Hulk). This led to occasional borderline DoS
false positives on sluggish web traffic, highlighting that models can become biased toward
temporal duration over volumetric packet density.
• Payload and Encryption Vulnerabilities: While tabular models reliably identify cleartext
protocol artifacts (such as predictable payload distributions in FTP brute-force attempts),
identical credential attacks transported across encrypted channels (such as SSH) yield altered
packet distributions and encrypted payloads that evade artifact-dependent decision trees.

8.5

Concluding Remarks

The ultimate takeaway of the NIDAS project is that benchmark test accuracy, while a vital
developmental baseline, represents only a laboratory metric. The true measure of an operational
intrusion detection system lies in identifying its operational breaking points under live conditions
and understanding the root causes of misclassifications. Flow-level machine learning provides
an exceptionally fast, high-throughput mechanism for intercepting volumetric floods and
high-intensity exploits. However, achieving production-grade resilience demands a hybrid
architecture that augments statistical tabular ensembles with protocol-level heuristic filters,
multi-flow connection tracking, and continuous localized adaptation.

9.

Future Work

While the NIDAS implementation establishes a complete and validated operational framework,
several promising directions are identified to advance the system toward enterprise-scale
cybersecurity deployment:

9.1

Continual Learning and Adaptive Concept Drift Mitigation

A persistent challenge in production intrusion detection is concept drift, where network traffic
distributions evolve dynamically due to new software deployments, operating system updates,
and evolving adversary tactics. In the current architecture, model retraining is conducted offline
using curated historical partitions. Future iterations should incorporate streaming continual
learning mechanisms, such as Hoeffding Adaptive Trees and experience-replay buffers, allowing
the base estimators to assimilate incremental updates from validated live traffic without suffering
from catastrophic forgetting. Furthermore, integrating statistical divergence monitors (such as
the Population Stability Index (PSI) and Wasserstein distance computed over rolling windows
of flow inter-arrival times) would enable automated triggering of localized retraining routines
whenever significant distribution shifts are detected.

9.2

Explainable AI (XAI) and Real-Time SHAP Attributions

In operational Security Operations Centers (SOCs), automated alerts must be accompanied by
transparent rationale to enable rapid triage and incident response. While the current dashboard
surfaces calibrated class probabilities, integrating real-time Explainable AI (XAI) techniques
represents a crucial enhancement. Implementing an optimized TreeSHAP (SHapley Additive
exPlanations) engine within the inference pipeline would compute exact feature contribution
vectors for every flagged connection. For instance, when a flow is classified as DoS, the
interface could present an immediate local attribution waterfall chart indicating that elevated
Flow Duration and extreme Bwd Packet Length Std contributed +0.42 and +0.35 respectively
toward the malicious score. Optimizing TreeSHAP tree traversal through path memoization
will ensure that explanatory attribution adds less than 1.5 milliseconds of latency to the alerting
dispatch.

9.3

Hardware Acceleration and Kernel-Level Packet Inspection

The current Python-based CICFlowMeter operates in user space via standard network sockets,
which delivers dependable throughput for monitoring standard local subnets but introduces
operating system context-switching overhead under line-rate gigabit flooding. Future work will
investigate offloading flow extraction directly into the Linux operating system kernel using eBPF
(Extended Berkeley Packet Filter) and XDP (eXpress Data Path). By performing packet hashing,
Department of Computer Applications, MACE

62

Real-Time Network Intrusion Detection and Alert System

timestamping, and counter accumulation within the driver layer before packets reach the OS
networking stack, throughput can scale toward 10 Gbps and 100 Gbps enterprise backbones.
Concurrently, converting the serialized ensemble into optimized Open Neural Network Exchange
(ONNX) or TensorRT binaries will allow parallelized tree evaluation on dedicated edge inference
accelerators.

9.4

Hybrid Unsupervised Zero-Day Threat Interception

The proposed ensemble excels at multi-class classification across known attack families
(achieving 99.94% test accuracy). However, purely supervised learning remains inherently
constrained by the scope of historical training labels. To protect against novel zero-day
exploits and sophisticated advanced persistent threats (APTs), future iterations will couple
the supervised soft-voting ensemble with an unsupervised anomaly detection branch, such as a
deep convolutional Autoencoder or an Isolation Forest fitted exclusively on legitimate baseline
traffic. When incoming flows exhibit low supervised confidence alongside high autoencoder
reconstruction error, the system will flag the traffic as an uncharacterized zero-day anomaly,
quarantining the connection and routing telemetry to human security analysts for forensic
payload analysis.
