\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

Network security has become increasingly critical as modern cyberattacks grow in frequency, stealth, and complexity, threatening organizational digital infrastructure across all sectors. Traditional signature-based intrusion detection systems struggle to detect novel zero-day exploits, evasive low-rate probing, and evolving volumetric attack vectors. Machine learning offers a promising paradigm for adaptive anomaly detection, yet operational implementations frequently encounter significant challenges, including severe class imbalance between benign and malicious flows, prohibitive inference latency, and the absence of end-to-end integration between theoretical offline models and live packet capture pipelines.

This work presents the Real-Time Network Intrusion Detection and Alert System (NIDAS), an end-to-end machine learning platform engineered for continuous network monitoring and automated threat alerting. The system is trained and evaluated on a curated corpus of 1,799,905 network flows derived from the CIC-IDS2017 benchmark, covering Normal Traffic alongside four prevalent attack vectors: Denial of Service (DoS), Distributed Denial of Service (DDoS), Port Scanning, and Brute Force. A rigorous five-stage feature selection methodology---comprising zero-variance removal, collinearity reduction ($r > 0.90$), Kruskal-Wallis non-parametric significance testing, Random Forest feature importance scoring, and domain validation---prunes 77 raw flow features down to an optimal 40-feature operational space.

To overcome the operational limitations of single-model classifiers, NIDAS employs a soft-voting ensemble coupling Random Forest and Extreme Gradient Boosting (XGBoost). Random Forest ($B = 200$ trees) provides variance dampening across noisy packet metrics, while XGBoost (300 estimators with histogram-based binning) supplies precise bias reduction for difficult boundary distinctions. Balanced sample weighting counters class imbalance without introducing synthetic oversampling artifacts. On an independent test set of 394,168 flows, the ensemble achieves 99.88\% overall accuracy, a macro-averaged F1-score of 99.76\%, and sub-millisecond per-flow inference latency ($< 0.6$~ms).

The operational pipeline is deployed as a lightweight client-server application featuring asynchronous live packet capture via Npcap/libpcap, online feature extraction using Welford's algorithm, and a stateful cross-flow sliding window detector for stealthy port scans. Inferred threats are categorized into color-coded severity tiers (Critical, High, Medium) and streamed via FastAPI WebSockets to an interactive React SOC dashboard with automated self-traffic suppression. The result is a robust, production-ready solution that bridges theoretical intrusion detection with low-overhead, real-time security operations.

\chapter{Introduction}
The rapid expansion of digital infrastructure has made computer networks a primary target for malicious actors. Global cybercrime damages are projected to exceed ten trillion dollars annually in 2025--2026, with India seeing sharp rises in DDoS and ransomware attacks targeting banking, healthcare, and government networks.

An Intrusion Detection System (IDS) monitors network traffic for unauthorized access or malicious behaviour. Signature-based systems match traffic against known attack patterns; anomaly-based systems flag deviations from a learned baseline. Signature-based approaches fail against zero-day exploits, driving research into ML-based detection capable of generalizing to unseen attacks.

A persistent gap exists between academic IDS research and practical deployment. Most published systems evaluate on static datasets without addressing real-time operational pipelines, continuous alerting, or analyst-facing interfaces, limiting operational value. A further challenge is severe class imbalance: benign flows dominate real traffic, and models that ignore this risk high false-negative rates on minority attack classes.

This project is motivated by CERT-In mandates for faster incident detection and the expanded network perimeter from hybrid cloud and remote work environments.

\textbf{Objectives:}
\vspace{-0.6em}
\begin{enumerate}
    \item Train a Random Forest + XGBoost ensemble on the combined CIC-IDS2017 and CSE-CIC-IDS2018 benchmark for multi-class intrusion detection.
    \item Implement a real-time alert mechanism upon detection of anomalous flows.
    \item Build a real-time detection pipeline: live flow feature extraction $\rightarrow$ ensemble classification $\rightarrow$ alerting and telemetry.
    \item Comparatively evaluate RF, XGBoost, and the ensemble on accuracy, precision, recall, and F1.
\end{enumerate}

NIDAS is designed as an end-to-end real-time intrusion detection pipeline that processes network traffic via a custom CICFlowMeter implementation. Each flow is classified into: Normal Traffic, DoS, DDoS, Port Scanning, or Brute Force. Detected anomalies trigger timestamped alerts with predicted attack type and confidence score. A React JS dashboard surfaces live flow classifications; a FastAPI backend handles communication between the detection engine and UI.

The key contribution is end-to-end integration of ensemble detection with real-time alerting and dashboard visualization operationally actionable, not just accurate.

\section{Literature Review}
\textbf{PAPER I}

\textit{Ness S, Eswarakrishnan V, Sridharan H, Shinde V, Janapareddy N V P, \& Dhanawat V. (2025). Anomaly detection in network traffic using advanced machine learning techniques. IEEE Access, vol.\ 13, pp.\ 16133--16149.}

This paper investigates various machine learning models for detecting anomalies in network traffic, focusing on overcoming challenges like class imbalance and feature complexity. Accurate anomaly detection serves as a proactive measure to safeguard network integrity and identify dynamic security risks.

The authors utilize five machine learning algorithms: Isolation Forest, Naive Bayes, XGBoost, LightGBM, and Support Vector Machine (SVM). The study relies on the KDDCup'99 dataset, which includes normal activity and multiple attack types like DoS, Probe, Remote to Local (R2L), and User to Root (U2R). Data preprocessing involves the Synthetic Minority Over-sampling Technique (SMOTE) for balancing classes, label encoding for categorical features, and Principal Component Analysis (PCA) for feature extraction and dimensionality reduction.

The models were evaluated using 5-fold cross-validation with metrics including accuracy, precision, recall, and F1-score. LightGBM achieved the highest test accuracy (1.0) and F1-score (0.85). SVM also demonstrated strong performance with a test accuracy of 0.85 and F1-score of 0.86. Conversely, Isolation Forest performed poorly with a test accuracy of 0.40, struggling with the dataset's complexity.

The study concludes that advanced ensemble and gradient boosting methods like LightGBM and XGBoost, alongside SVM, offer robust detection capabilities for network traffic anomalies. Future work suggests integrating deep learning techniques like CNNs and RNNs, using ensemble methods to reduce false positives, and applying models to newer datasets like CICIDS and NSL-KDD.

\textbf{PAPER II}

\textit{Fathima AHN, Ibrahim SPS, Khraisat A. Enhancing Network Traffic Anomaly Detection: Leveraging Temporal Correlation Index in a Hybrid Framework. IEEE Access. 2024 Sep 11;12:136805--136824.}

This paper introduces the Temporal Metric-Driven GRU Embedded Generative Neural Network (TMG-GRU-VAE) to improve the identification of network traffic irregularities. Traditional models often emphasize detecting network attacks but struggle to capture the dynamic and temporal aspects of network traffic, making it difficult to detect subtle behavioral shifts.

The proposed methodology combines Gated Recurrent Units (GRU) with Variational Autoencoders (VAE) to effectively learn normal temporal patterns in sequence data. Additionally, the authors propose a novel Temporal Correlation Index (TCI) score to assess temporal behavior and establish dynamic anomaly detection thresholds. The study utilizes the CIC-IDS-2017 and CIC-IDS-2018 datasets, splitting the preprocessed data into 70\% training and 30\% testing subsets.

The models were evaluated using accuracy, precision, recall, F1-score, and false alarm rates. The TMG-GRU-VAE model combined with TCI achieved significant reductions in False Positives. Improvements in FP reduction ranged from 7.2\% to 12.9\% for CIC-IDS-2017, and 7.1\% to 14.1\% for CIC-IDS-2018. The GRU-VAE with TCI achieved the highest True Positive rates and the lowest FP rates.

The research demonstrates that integrating temporal correlation metrics with hybrid deep learning frameworks substantially reduces false alarms and improves overall anomaly detection accuracy. Future work aims to develop explainable AI models to enhance interpretability and confidence in detection results, particularly for addressing zero-day threats.

\textbf{PAPER III}

\textit{Ji C, Liu H, Dai W. Hybrid Model for Network Traffic Anomaly Detection Based on Parallel Two-Stage Feature Fusion. IEEE Access. 2025 Feb 4;13:27310--27324.}

The paper proposes GRU-ResCBANet, a deep learning hybrid model tailored for network traffic anomaly detection. The model addresses issues such as low detection rates for minority attack classes and high false alarm rates by employing a parallel two-stage feature extraction and fusion technique.

In the first stage, the ResCBANet module uses an improved residual network enhanced with a Convolutional Block Attention Module (CBAM) to extract spatial features and channel attention. In parallel, a Gated Recurrent Unit (GRU) module captures temporal dependencies. These features are fused and passed to a fully connected classification layer using a Softmax activation function. The model was evaluated on the NSL-KDD, UNSW-NB15, and CICIDS2017 datasets, which were preprocessed and reduced in dimensionality using ANOVA for feature selection.

GRU-ResCBANet delivered state-of-the-art results. For binary classification, it achieved accuracies of 99.70\% on NSL-KDD, 99.16\% on UNSW-NB15, and 99.83\% on CICIDS2017. For multi-class classification, accuracies reached 99.69\%, 98.23\%, and 99.79\% respectively. The model consistently outperformed eight other comparison models, including SVM, RF, 2D-CNN, and CNN-LSTM.

The study concludes that parallel integration of GRU and ResCBANet successfully captures comprehensive feature representations, significantly boosting anomaly detection accuracy. Future directions include exploring model compression for edge computing, applying oversampling strategies for class imbalance, and integrating federated learning for privacy-preserving distributed security.

\section{Findings and Proposals}

\textbf{Findings}

The reviewed literature establishes several consistent findings. Ensemble and fusion-based approaches uniformly outperform single-model classifiers in network traffic anomaly detection, across both traditional ML and deep learning paradigms. The CIC-IDS2017 dataset is the dominant benchmark in current IDS research and is the standard against which results from this project are comparable. Temporal features, particularly IAT-based features, carry significant discriminative information that improves detection of attack types with characteristic timing signatures. Despite the progress in detection accuracy, none of the three reviewed papers implement a real-time operational pipeline; all evaluate models in an offline, batch mode.

\textbf{Identified Gap}

The common gap across all three reviewed papers is the absence of a real-time alert mechanism. Each paper treats intrusion detection as a classification task on a static dataset, with no consideration of how detected anomalies are surfaced to an operator as they occur. This gap is practically significant: a model with high batch accuracy that cannot generate timely alerts provides no operational advantage over a post-hoc log analysis.

\textbf{Proposal}

This project proposes to close this gap by integrating a real-time alerting mechanism directly into the ensemble detection pipeline. The proposed system extends the soft-voting RF + XGBoost ensemble validated by Ness et al.\ with a FastAPI backend that classifies incoming flows in real time and triggers alert notifications upon detection of anomalous traffic. A React JS dashboard surfaces these alerts to the operator with predicted attack category and ensemble confidence score. This integration of detection and alerting constitutes the novel contribution of this project over the reviewed literature.

\chapter{System Analysis}

\section{Analysis of the Dataset}

\subsection{About the Dataset}

To establish a resilient intrusion detection system capable of mitigating domain-specific vulnerabilities, this project integrates two widely recognized benchmark datasets developed by the Canadian Institute for Cybersecurity: CIC-IDS2017 and CSE-CIC-IDS2018. Both datasets simulate realistic enterprise network traffic containing diverse, state-of-the-art attack executions alongside normal background user activity, captured using the network traffic profiling tool CICFlowMeter.

The CIC-IDS2017 benchmark comprises eight raw CSV captures totaling 2,830,743 network flow records across 79 columns. The CSE-CIC-IDS2018 benchmark, collected in a collaborative effort between the Communications Security Establishment (CSE) and the Canadian Institute for Cybersecurity (CIC) on AWS infrastructure, encompasses six targeted attack captures used in this study (BruteForce, BruteForce2, BruteForceSSH, DDoS, DoS, and DoS2) totaling 6,291,449 raw flow records across 80 columns. To harmonize the two heterogeneous schemas, abbreviated column headers in the 2018 dataset (e.g., Dst Port, Tot Fwd Pkts, Pkt Len Mean) were systematically mapped to the standardized naming conventions of CIC-IDS2017. Internal repeated header lines and non-flow metadata attributes (Protocol and Timestamp) were excluded, yielding a combined pre-cleaning corpus of 9,117,071 flow records across 77 shared numeric features.

The raw multiclass labels across both datasets were consolidated into five harmonized traffic categories:
\begin{itemize}
    \item \textbf{Normal Traffic:} Merging BENIGN from CIC-IDS2017 and benign from CSE-CIC-IDS2018.
    \item \textbf{Denial of Service (DoS):} Aggregating DoS Hulk, DoS GoldenEye, DoS slowloris, and DoS Slowhttptest from 2017 with dos attacks-goldeneye, dos attacks-slowloris, dos attacks-hulk, and dos attacks-slowhttptest from 2018.
    \item \textbf{Distributed Denial of Service (DDoS):} Combining DDoS from 2017 with ddos attacks-loic-http, ddos attack-loic-udp, and ddos attack-hoic from 2018.
    \item \textbf{Brute Force:} Unifying credential-guessing attacks including FTP-Patator and SSH-Patator from 2017 with ftp-bruteforce and ssh-bruteforce from 2018.
    \item \textbf{Port Scan:} Incorporating port scanning probe activity (PortScan from 2017).
\end{itemize}
\newpage
Peripheral attack categories outside these five focus domains (such as Bot, Infiltration, Web Attacks, and Heartbleed) were excluded, resulting in a cohesive multi-class dataset tailored for tabular machine learning algorithms.

\subsection{Explore the Dataset}

The combined dataset initially encompasses 9,117,071 flow records across 77 numeric features and two tracking attributes (Attack Type and Source). Statistical profiling of the combined corpus revealed several critical data hygiene and distribution challenges:
\begin{itemize}
    \item \textbf{Constant Features:} Eight feature columns exhibited zero variance across all 9.1 million records: Bwd PSH Flags, Bwd URG Flags, Fwd Avg Bytes/Bulk, Fwd Avg Packets/Bulk, Fwd Avg Bulk Rate, Bwd Avg Bytes/Bulk, Bwd Avg Packets/Bulk, and Bwd Avg Bulk Rate. Carrying no discriminative signal, these columns were slated for immediate removal, reducing the feature space to 69 numerical dimensions.
    \item \textbf{Missing and Infinite Values:} A total of 26,026 records contained infinite or NaN values in rate-dependent features (Flow Bytes/s and Flow Packets/s), caused by zero-duration flows dividing by zero time increments. These corrupted records represent under 0.29\% of the raw corpus and were removed.
    \item \textbf{Duplicate Records:} An extensive deduplication pass identified 2,263,887 duplicate flow records (approximately 24.9\% of valid rows). Removing these duplicates reduced the corpus to 6,827,158 unique records, preventing artificial inflation of model metrics and data leakage between train and test splits.
    \item \textbf{Severe Class Imbalance:} Among the 6,827,158 unique flows, benign background traffic heavily predominated with 5,914,415 records (86.63\%), compared to 390,200 DoS records (5.72\%), 328,605 DDoS records (4.81\%), 103,244 Brute Force records (1.51\%), and 90,694 Port Scan records (1.33\%).
\end{itemize}

Descriptive statistics across the unified flow metrics highlight stark distributional skews. Flow Duration spans from 0 to 120 million microseconds with a low median, reflecting that the vast majority of legitimate and probe flows are short-lived, whereas DoS and slowloris attacks sustain extended connection durations. Packet length metrics exhibit strong bimodal tendencies: probe and scanning vectors concentrate near minimal payload thresholds (e.g., 3 to 6 bytes), whereas high-volume DDoS flooding attacks generate large payloads (mean exceeding 700 bytes).

\section{Data Preprocessing}

To transform the 9.12 million raw flow observations into an optimal, high-fidelity training dataset, a systematic data preprocessing and refinement pipeline was implemented.

\subsection{Data Cleaning}

A systematic five-stage data cleaning and preparation pipeline was applied to ensure dataset integrity and remove non-informative features:

\begin{enumerate}
    \item \textbf{Zero-Variance Column Removal:} The 8 constant columns identified during exploration were dropped, retaining 69 informative numeric features.
    \item \textbf{Infinity and Null Value Cleaning:} All infinite values ($\pm\infty$) were converted to NaN, and the 26,026 affected rows were eliminated, leaving 9,091,045 clean records.
    \item \textbf{Deduplication:} Exact duplicate rows across the feature space were purged, eliminating 2,263,887 records and yielding 6,827,158 unique flow records.
    \item \textbf{Benign Subsampling and Class Balancing:} In the unique corpus, Normal Traffic accounted for over 5.91 million records (86.6\%). Retaining all benign records would induce severe majority-class bias and excessive training overhead without adding behavioral variance. Consequently, Normal Traffic was randomly subsampled at 15\% (887,162 records) and combined with 100\% of all attack records (912,743 flows). This produced a balanced, highly representative dataset of 1,799,905 records composed of:
    \begin{itemize}
        \item Normal Traffic: 887,162 records (49.29\%)
        \item DoS: 390,200 records (21.68\%)
        \item DDoS: 328,605 records (18.26\%)
        \item Brute Force: 103,244 records (5.74\%)
        \item Port Scan: 90,694 records (5.04\%)
    \end{itemize}
    In terms of dataset origin, CSE-CIC-IDS2018 contributed 1,064,113 flows (59.12\%) and CIC-IDS2017 contributed 735,792 flows (40.88\%), ensuring robust cross-environment representation.
    \item \textbf{Categorical Label Encoding:} The target categorical variable (Attack Type) was mapped to integers using scikit-learn's LabelEncoder, assigning integer indices $0$ to $4$ corresponding to Brute Force, DDoS, DoS, Normal Traffic, and Port Scan.
\end{enumerate}

\subsection{Analysis of Feature Variables}

The unified dataset contains 69 candidate numeric features after removing zero-variance columns. Following the cleaning, feature selection, and domain-refinement pipeline, 40 features are retained for model training and deployment. These can be grouped into the following categories based on the aspect of network flow behaviour they capture.

Packet length features capture the size characteristics of packets in both forward (client-to-server) and backward (server-to-client) directions, including maximum, minimum, mean, and standard deviation values. Feature importance analysis identifies this group as the strongest family of discriminative features, with Bwd Packet Length Mean, Packet Length Std, Bwd Packet Length Std, and Fwd Packet Length Mean exhibiting high discriminative capacity. These features are particularly discriminative for DoS and DDoS attacks, which generate packets of characteristic sizes at high rates.

Inter-Arrival Time (IAT) features measure the time intervals between successive packets within a flow, computed separately for the overall flow, the forward sub-flow, and the backward sub-flow. Standard deviation, maximum, and minimum IAT values are included. As demonstrated by Fathima et al.\ (2024), temporal features of this nature carry significant discriminative information for attacks that exhibit periodic or bursty timing patterns.

Traffic volume features include Total Length of Fwd Packets, Total Fwd Packets, and Total Backward Packets, characterizing the overall data volume transferred in each direction. These complement packet length features for detecting volume-based attacks.

Flow-level throughput features include Flow Bytes/s, Flow Packets/s, and Bwd Packets/s, which characterize the volumetric rate of the flow.

TCP flag features record the presence of FIN, PSH, and ACK flags within the flow. These help distinguish connection setup and teardown patterns associated with specific attack types such as port scans.

TCP window and header features include the initial TCP window sizes in both directions, forward and backward header lengths, and minimum segment size, which reflect protocol-level behaviour that varies across attack types.

Active and Idle time features capture the periods of activity and inactivity within a flow. Active Max and Idle Mean are retained after feature selection.

Feature selection and refinement were executed in four stages:
\begin{enumerate}
    \item \textbf{Collinearity Filtering ($r > 0.98$):} Pearson correlation analysis evaluated on a stratified 50,000-sample subset revealed strong linear dependencies among subflow counters, bidirectional segment statistics, and forward/backward duplicates. Sixteen redundant collinear features were pruned: Fwd IAT Total, Subflow Fwd Packets, Subflow Bwd Packets, Subflow Fwd Bytes, Subflow Bwd Bytes, Avg Fwd Segment Size, Avg Bwd Segment Size, Fwd PSH Flags, Fwd URG Flags, ECE Flag Count, Average Packet Size, Fwd IAT Max, Fwd Packets/s, Idle Max, Idle Min, and Down/Up Ratio. This reduced the feature space from 69 to 53 features.
    \item \textbf{Kruskal-Wallis Hypothesis Testing:} A non-parametric Kruskal-Wallis $H$-test evaluated whether each feature exhibited statistically significant distribution differences across the five target classes. CWE Flag Count failed to demonstrate significance ($p = 0.612 > 0.05$) and was removed, reducing the feature space to 52 features.
    \item \textbf{Random Forest Feature Importance Pruning:} A Random Forest classifier was fitted on the sample to compute Gini impurity-based feature importances. Features falling within the bottom 10\% quantile were eliminated: URG Flag Count, Active Mean, Active Min, Idle Std, Active Std, and SYN Flag Count, yielding 46 candidate features.
    \item \textbf{Domain Generalization and Redundancy Pruning:} Prior to model training, six additional features were eliminated: Destination Port (pruned to prevent shortcut learning and overfitting to static port numbers, ensuring port-agnostic generalization), Packet Length Variance (exact mathematical collinearity with Packet Length Std), Total Length of Bwd Packets, Bwd Packet Length Min, Fwd IAT Mean, and Bwd IAT Mean (which showed high multi-collinearity with overall flow timing and packet statistics).
\end{enumerate}
This rigorous pruning process established the final, high-impact set of 40 features used for model training, offline evaluation, and live inference. Feature scaling using RobustScaler was fitted exclusively on the training split to standardize features with wide dynamic ranges and heavy-tailed distributions while providing resilience against extreme network burst outliers, followed by discriminative feature weighting.

\section{Analysis of Architecture and Algorithms}

The Real-Time Network Intrusion Detection and Alert System (NIDAS) employs a hybrid ensemble learning architecture designed to deliver high-throughput, low-latency threat detection across live network traffic. Structured network telemetry is characterized by extreme non-linearities, heavy-tailed burst distributions, and severe class imbalances between benign and malicious flows. Single-model classifiers frequently suffer from an operational trade-off: high-variance models overfit to benign network fluctuations, generating excessive false alarms, whereas high-bias models fail to capture stealthy, low-volume intrusions. To overcome these limitations, NIDAS couples Random Forest and Extreme Gradient Boosting (XGBoost) within a soft-voting ensemble framework, combining the variance-reduction strengths of bagging with the bias-reduction precision of gradient boosting. The following sections provide an in-depth analysis of the mathematical foundations, operational strengths, inherent weaknesses, and project-specific scope of each proposed algorithm.

\subsection{Detailed Study Report of the Proposed Algorithms}

\subsubsection*{Random Forest}

Random Forest is a non-parametric ensemble learning method based on bootstrap aggregating (bagging) of unpruned or depth-constrained decision trees. During training, the algorithm constructs $B = 200$ individual classification trees using bootstrap samples drawn with replacement from the $1.58$ million training flows. At each node split, instead of evaluating all candidate dimensions across the feature space, a random subset of size $m = 0.4 \times 40 = 16$ features is sampled. Splitting criteria evaluate impurity reduction---such as Gini impurity, defined as $\text{Gini}(p) = 1 - \sum_{c=1}^{C} p_c^2$---to recursively partition the high-dimensional flow metric space. The final prediction for an input flow vector $x$ is formed by aggregating posterior probability distributions across all individual trees:
\begin{equation}
P_{\text{RF}}(y = c \mid x) = \frac{1}{B} \sum_{b=1}^{B} P_b(y = c \mid x)
\end{equation}
This dual randomization protocol (subsampling training instances and subsampling candidate features) effectively decorrelates individual decision trees, substantially lowering the overall variance of the ensemble without elevating its bias. Restricting the maximum tree depth to 10 ($max\_depth = 10$) prevents individual estimators from overfitting to transient network artifacts or memorizing specific port signatures.

Strengths: Exceptional resistance to overfitting on high-dimensional tabular data through variance dampening; native resilience to noisy, skewed, or collinear network traffic features without requiring strict Gaussian assumptions; invariance to monotonic feature transformations, ensuring stable decision thresholds across metrics spanning several orders of magnitude; transparent model interpretability via Mean Decrease in Impurity (MDI) feature importance rankings; and high computational parallelization during training across all available CPU cores ($n\_jobs = -1$).

Weaknesses: Significant memory footprint during deployment because the complete structure of 200 multi-class decision trees must reside concurrently in RAM; inference latency scales directly with tree count and depth, presenting potential computational overhead during extreme packet floods compared to compact linear models; inability to extrapolate beyond the numerical boundaries observed during training; tendency to favor majority traffic classes if class imbalances are unweighted; and redundant tree node partitions when processing correlated flow characteristics.

Scope of the algorithm with respect to this project: Within the NIDAS architecture, Random Forest provides the stable, variance-reducing foundation necessary to handle real-world network burstiness. Real-time packet telemetry frequently exhibits severe outliers and multi-modal distributions that cause volatile predictions in single-tree or parametric detectors. Operating on the 40 preprocessed flow features with balanced sample weighting, Random Forest reliably anchors classification boundaries across large volumes of normal traffic while preserving sensitivity to minority attack patterns. In deployment, its tree traversal executes in under 0.6 milliseconds per flow, ensuring continuous operation well within the sub-millisecond latency budget required for live socket monitoring.

Justification: Ness et al.\ (2025), in a multi-model comparison on network traffic anomaly detection, demonstrated that tree-based ensemble methods consistently outperform single-model classifiers on structured network flow data. Fathima et al.\ (2024) validate their hybrid detection framework on the CIC-IDS2017 dataset, the same benchmark used here, directly supporting Random Forest's inclusion as a base learner.

\subsubsection*{XGBoost}

Extreme Gradient Boosting (XGBoost) is a scalable and highly optimized gradient tree boosting framework that constructs an ensemble of decision trees sequentially. Rather than building trees independently in parallel, XGBoost builds trees additively: at each iteration $t$, a new regression tree $f_t(x)$ is trained to predict and minimize the negative gradient of the loss function with respect to the accumulated predictions of the preceding ensemble $\hat{y}^{(t-1)}$:
\begin{equation}
\mathcal{L}^{(t)} = \sum_{i=1}^{N} l\left(y_i, \hat{y}_i^{(t-1)} + f_t(x_i)\right) + \Omega(f_t)
\end{equation}
where the regularization penalty on tree complexity, leaf count $T$, and leaf weights $w$ is formulated as:
\begin{equation}
\Omega(f_t) = \gamma T + \frac{1}{2} \lambda \sum_{j=1}^{T} w_j^2 + \alpha \sum_{j=1}^{T} |w_j|
\end{equation}
XGBoost applies a second-order Taylor expansion to approximate the loss function, incorporating both first-order gradients $g_i$ and second-order Hessian statistics $h_i$ to determine optimal leaf split values analytically. In NIDAS, multi-class classification across the five categories is achieved using the multi-class logarithmic loss objective ($eval\_metric='mlogloss'$), producing softmax-normalized probability distributions. Scalability across $1.58$ million training flows is achieved via the histogram-based split-finding algorithm ($tree\_method='hist'$), which bins continuous feature values into discrete bins, drastically accelerating training and enabling GPU acceleration.

Strengths: State-of-the-art predictive accuracy on structured tabular datasets via sequential bias reduction; accelerated second-order Taylor optimization incorporating Hessian curvature for fast and stable convergence; explicit L1 and L2 regularization that prevents leaf over-specialization on anomalous noise; GPU-accelerated histogram binning enabling rapid model fitting across millions of network flows; and calibrated multi-class probability outputs through softmax normalization.

Weaknesses: Sequential tree construction prevents inter-tree parallelization, making full training iterations computationally demanding if unconstrained; heightened vulnerability to noise and label noise if learning rates are overly aggressive; acute sensitivity to hyperparameter combinations (learning rate, tree depth, subsample ratio, and regularization penalties) necessitating systematic grid tuning; sequential tree traversal during inference requiring careful memory caching; and reduced generalization capacity when confronted with novel zero-day attack vectors whose gradient trajectories diverge drastically from historical training distributions.

Scope of the algorithm with respect to this project: In the NIDAS pipeline, XGBoost operates as the high-precision, bias-reducing specialist dedicated to resolving difficult boundary distinctions. Low-volume intrusions such as stealthy Port Scans and credential Brute Force attempts produce subtle statistical footprints that closely resemble standard benign communication. Configured with 300 estimators, a maximum depth of 6, a learning rate of 0.1, and discriminative feature weighting, XGBoost focuses gradient descent optimization on these fine-grained edge cases. In the live monitoring pipeline, XGBoost generates sharp posterior probability vectors that elevate threat detection recall without escalating false alarms, identifying low-rate probing activities before attackers can complete their reconnaissance phases.

Justification: Ness et al.\ (2025) evaluated XGBoost directly against four other models on network traffic anomaly detection, finding it among the strongest individual classifiers with a test accuracy of 0.83 and F1-score of 0.84. Ji C et al.\ (2025), evaluated on the same CIC-IDS2017 dataset, provide a direct performance reference point: their GRU-ResCBANet model achieved 99.79\% multi-class accuracy, against which the ensemble's results can be situated.

\subsubsection*{Soft-Voting Ensemble}

The proposed detection engine combines Random Forest and XGBoost into a soft-voting ensemble, fusing their complementary inductive biases through continuous probability averaging. For an input flow feature vector $x \in \mathbb{R}^{40}$, each base model $m \in \{\text{RF}, \text{XGB}\}$ computes a posterior class probability distribution over the set of five traffic classes $C$:
\begin{equation}
P_m(y = c \mid x), \quad \forall c \in C, \quad \sum_{c \in C} P_m(y = c \mid x) = 1
\end{equation}
The soft-voting ensemble synthesizes these probability outputs into a unified consensus probability vector:
\begin{equation}
P_{\text{ens}}(y = c \mid x) = \frac{1}{2}\left(P_{\text{RF}}(y = c \mid x) + P_{\text{XGB}}(y = c \mid x)\right)
\end{equation}
The final classification decision is determined via the argmax operator:
\begin{equation}
\hat{y} = \arg\max_{c \in C} P_{\text{ens}}(y = c \mid x)
\end{equation}
Unlike hard voting, which tallies discrete class votes and discards confidence information, soft voting incorporates continuous model confidence. When both estimators agree with strong conviction, the probability is reinforced; when one estimator is uncertain or borderline, the averaged distribution dampens erroneous certainty, effectively preventing outlier classifications from propagating into the alerting pipeline.

Strengths: Synergistic fusion of complementary inductive biases, pairing the variance-reduction stability of bagging with the bias-minimization precision of boosting; significant reduction in false positive generation, achieving an operational benign false alarm rate of 0.021\%; well-calibrated confidence estimates suitable for dynamic risk thresholding; superior noise tolerance and robustness against corrupted feature values; and outstanding multi-class benchmark performance (99.94\% accuracy and 0.9994 macro F1) rivaling complex deep learning architectures while retaining superior inference speed.

Weaknesses: Increased memory overhead in deployment because both model binaries, feature scalers, and weight vectors must be held persistently in system memory; dual-model inference requires evaluating both tree ensembles, approximately doubling CPU processing time compared to a standalone classifier; inability to rectify errors when both base estimators share correlated blind spots against novel protocol exploits; and strict synchronization requirements to ensure identical feature ordering and preprocessing transformations across both underlying software frameworks.

Scope of the algorithm with respect to this project: The soft-voting ensemble serves as the central operational intelligence core of the NIDAS system, bridging the divide between high-accuracy offline research and dependable real-time production deployment. A fundamental challenge in deploying intrusion detection systems is alert fatigue, where security operators become desensitized to warnings due to frequent false alarms. By requiring dual-model probabilistic consensus, the ensemble suppresses erratic predictions and delivers trustworthy classifications across the 40 extracted bidirectional flow features. Operating within an end-to-end evaluation latency of 0.5 to 1.2 milliseconds per flow, the ensemble directly drives downstream operational logic---assigning threat severity levels (Critical for DDoS and DoS, High for Brute Force, Medium for Port Scan), triggering real-time terminal UI feeds, and appending forensic records to alert\_log.csv without overwhelming network administrators with false alarms.

Justification: Fathima et al.\ (2024) demonstrate that high false positive rates are the central practical failure mode of IDS systems. Ensemble soft voting directly addresses this by averaging probability vectors, pulling inflated attack probability predictions back toward the correct class. Ji C et al.\ (2025) provide a direct benchmark on intrusion detection: their deep learning hybrid architecture achieves 99.79\% multi-class accuracy, while the proposed RF + XGBoost soft-voting ensemble achieves 99.94\% accuracy on the combined benchmark, confirming that the ensemble is highly competitive with architecturally complex deep models.

In summary, each of the three algorithms fulfills a distinct, complementary function within the NIDAS architecture: Random Forest contributes essential variance reduction and stability across heavy-tailed, bursty network traffic; XGBoost delivers high-precision bias reduction and second-order gradient optimization to capture subtle, low-volume attack footprints; and the soft-voting ensemble synergistically unifies their continuous posterior probability vectors. By requiring probabilistic consensus across both learning paradigms, the system achieves superior multi-class detection accuracy while suppressing benign false alarms to 0.021\%, establishing the robust analytical foundation operationalized in the end-to-end processing pipeline detailed next.

Standalone Random Forest and XGBoost baselines are benchmarked against the soft-voting ensemble.
    
    \item \textbf{Final Model Saving:} The trained ensemble artifacts are serialized directly from the 80\% training split. To preserve empirical validity and prevent unverified data leakage, the models are not retrained on the full dataset, ensuring that all production artifacts strictly reflect the validated test partition boundaries.
    
    \item \textbf{Deployment and Real-Time Prediction:} In the operational deployment pipeline, live network traffic is captured via network sockets. The custom CICFlowMeter reassembles packets into bidirectional flows, extracts the 40 flow features, and formats them in the exact column ordering expected by the model. The real-time preprocessing stage verifies finite values, applies the pre-fitted RobustScaler, scales features using the discriminative weight vector, and executes soft-voting inference across both base models to yield the predicted attack class and confidence score.
    
    \item \textbf{Alert Generation and System Output:} If the predicted class is anomalous, the system assigns a severity rating (Critical for DDoS and DoS, High for Brute Force, Medium for Port Scan). Telemetry is appended to a persistent audit log (alert\_log.csv) containing timestamps, predicted classes, severity ratings, individual model votes, and confidence scores. Real-time notifications and colored feeds are surfaced through both a terminal CLI and the asynchronous FastAPI WebSocket backend to the interactive React JS SOC monitoring dashboard.

The soft-voting ensemble combines the distinct inductive biases of both estimators: Random Forest limits variance through bagging, while XGBoost performs gradient-guided error correction. By averaging the class probability vectors across both models, the ensemble produces calibrated predictions that mitigate single-model error spikes on ambiguous boundary traffic flows.

Although standalone XGBoost exhibits a marginally higher nominal accuracy on the static test split (99.95\% compared to 99.94\% for the ensemble, representing a difference of only 39 flows out of 394,168), the soft-voting ensemble was deliberately selected as the operational core of NIDAS. In real-world intrusion detection, relying exclusively on static offline accuracy introduces critical operational hazards. Standalone gradient-boosted models optimize aggressively against empirical training distributions, rendering them susceptible to subtle benchmark artifacts, synthetic traffic generation patterns, and localized sensor noise. When exposed to live network environments characterized by unexpected packet jitter, dynamic MTU variations, and gradual concept drift, an over-specialized boosting model can produce erratic, high-confidence misclassifications.

Integrating Random Forest's variance-reduction bagging mechanism into the ensemble provides an essential regularizing counterweight. In operational network security, the primary operational bottleneck is not marginal offline accuracy, but alert fatigue induced by false alarms on legitimate background traffic. When high-volume benign traffic encounters the detector, isolated statistical spikes can cause a single classifier to output overconfident threat classifications. Under the soft-voting scheme, an alarm is triggered only when supported by continuous probabilistic consensus between two fundamentally distinct learning algorithms. If an anomalous normal flow triggers a spurious prediction in one model, the conservative posterior distribution of the second estimator moderates the aggregate score, successfully suppressing false positives. This collaborative consensus drives the ensemble's false positive rate on benign traffic down to 0.021\%, ensuring that security operators can trust alerts without being overwhelmed by false alarms.

Furthermore, soft probability averaging generates smoothly distributed confidence vectors across all five traffic classes rather than polarized, brittle binary outputs. In the production deployment of NIDAS, these calibrated confidence scores directly feed the alerting engine, allowing the system to differentiate between unambiguous high-volume intrusions (such as volumetric DDoS and DoS floods) and ambiguous low-rate anomalies (such as stealthy port scans). High-confidence detections trigger immediate high-priority terminal alerts and automated log dispatches, whereas borderline predictions are flagged for secondary inspection. This multi-tiered operational triage is uniquely enabled by the ensemble's balanced posterior probabilities, validating its selection over a standalone classifier despite the negligible 0.01\% difference in benchmark accuracy.

The empirical evaluation validates the primary research hypothesis: a soft-voting ensemble combining Random Forest and XGBoost, trained with discriminative feature weighting, balanced sample weights, and RobustScaler normalization, delivers near-perfect classification across diverse attack families. The key strength of the proposed system lies in its balanced sensitivity: minority attack classes such as Brute Force and Port Scan achieve F1-scores of 0.9997 and 0.9992 respectively, directly validating the combination of balanced sample weighting and discriminative feature weighting (scaling high-importance features by $3.0\times$ and medium-importance features by $2.0\times$). RobustScaler effectively handles extreme burst distributions in network traffic without being distorted by outlier values.

A consideration for live deployment is that incoming traffic must be processed using the identical 40-feature extraction logic implemented by CICFlowMeter. Deviations in feature definitions or network interface buffering could impact classification confidence, which is mitigated in NIDAS through the dedicated CICFlowMeter clone integrated into the pipeline.

\section{Model Implementation}

\subsection{Architecture of the Custom Flow Extraction Engine}

Network packets captured at the socket or network interface card (NIC) layer arrive as discrete, unorganized frames. To transform raw packet streams into the structured 40-dimensional feature vectors expected by the ensemble, a custom, lightweight Python reimplementation of CICFlowMeter was engineered into the pipeline.

The flow generator tracks active communication sessions using a bidirectional 5-tuple hash key comprising:
\begin{equation}
\text{Flow Key} = \left(\text{Source IP}, \text{Destination IP}, \text{Source Port}, \text{Destination Port}, \text{Protocol}\right)
\end{equation}
When a packet is intercepted, the engine checks whether its forward or reverse 5-tuple already exists in an active flow cache. If the reverse key exists, the packet is flagged as a backward (server-to-client) transmission; otherwise, a new flow record is instantiated with the packet designated as forward (client-to-server).

To maintain constant memory bounds during high-throughput network monitoring, the flow engine manages active sessions through dual expiration timers:
\begin{enumerate}
    \item \textbf{Idle Timeout ($T_{\text{idle}} = 5\text{ s}$):} If no packets are observed across a flow for five consecutive seconds, the connection is deemed terminated (or abandoned), triggered for feature finalization, and dispatched to the inference queue.
    \item \textbf{Active Timeout ($T_{\text{active}} = 120\text{ s}$):} Sustained connections that transmit packets continuously without idle gaps (such as large file transfers or volumetric DoS/DDoS flooding) are forcibly flushed every 120 seconds. This prevents long-lived flows from delaying attack detection and eliminates unbounded cache memory growth.
\end{enumerate}

\subsection{Online Metric Computation via Welford's Algorithm}

Buffering thousands of individual packet payloads to compute statistical properties (such as mean and variance of packet lengths and inter-arrival times) is computationally prohibitive at line rate. To achieve sub-millisecond execution with a memory footprint under 45 MB, the custom flow generator implements Welford's algorithm for numerically stable, single-pass computation of running statistics.

For each incoming packet with metric value $x_k$ at packet index $k$, the running mean $M_k$ and sum of squared differences $S_k$ are updated incrementally:
\begin{equation}
M_k = M_{k-1} + \frac{x_k - M_{k-1}}{k}
\end{equation}
\begin{equation}
S_k = S_{k-1} + (x_k - M_{k-1})(x_k - M_k)
\end{equation}
The sample variance and standard deviation are retrieved instantaneously upon flow termination:
\begin{equation}
\sigma_k^2 = \frac{S_k}{k - 1}, \quad \sigma_k = \sqrt{\sigma_k^2}
\end{equation}
This allows forward, backward, and global packet length and inter-arrival time statistics to be maintained with constant $O(1)$ time complexity per packet and zero raw payload buffering.

\subsection{Inference Pipeline and Alert Generation}

Upon flow termination, the finalized record is handed over to the Python inference pipeline. The execution sequence follows five deterministic stages:
\begin{enumerate}
    \item \textbf{Feature Ordering and Alignment:} The 40 extracted metrics are mapped into the exact sequential feature ordering established during offline model training.
    \item \textbf{Sanitization and Standardization:} Infinite values ($\pm\infty$) resulting from zero-duration divisions are replaced with NaN and handled. The pre-fitted RobustScaler standardizes the numeric vector, followed by multiplication by the discriminative feature weight vector ($3.0\times$ on primary flow dynamics, $2.0\times$ on medium-importance features).
    \item \textbf{Dual-Model Consensus Inference:} The standardized vector is evaluated by both Random Forest and XGBoost base estimators, generating continuous posterior probability distributions across the five classes. Soft probability averaging computes the consensus confidence vector.
    \item \textbf{Threat Severity Assignment:} If the argmax prediction corresponds to an anomaly, a threat record is generated assigning a calibrated severity rating (Critical for DDoS and DoS, High for Brute Force, Medium for Port Scan).
    \item \textbf{Audit Logging and Telemetry Dispatch:} Telemetry containing timestamps, socket addresses, predicted classifications, model votes, and confidence scores is appended to alert\_log.csv for forensic auditability, while simultaneously streaming to the terminal CLI and web dashboard.
\end{enumerate}

\subsection{Live Capture Optimization and Flow Responsiveness}

Deploying the inference pipeline on live network interfaces revealed several operational considerations that do not arise during offline dataset processing. Specific engineering adjustments were implemented to ensure system responsiveness and prevent false alarms:

\begin{enumerate}
    \item \textbf{Flow Inactivity Timeout Tuning:} In live network environments, persistent TCP connections (such as HTTP keep-alive channels) often experience long idle gaps. Under default CICFlowMeter settings with a 120-second inactivity timeout and a 10-second sweep interval, completed flow records remained buffered in memory for up to 130 seconds before being finalized and displayed. By reducing the flow timeout to 30 seconds and the cleanup sweep interval to 5 seconds, worst-case latency for emitting completed flows dropped from approximately 130 seconds to 35 seconds without prematurely truncating active sessions.
    \item \textbf{Single-Threaded Estimator Locking:} Scapy executes its packet sniffing loop on a dedicated thread while passing completed flows to the prediction pipeline. By default, both Random Forest and XGBoost attempt to utilize all CPU cores via joblib multiprocessing. In a live capture loop, spawning sub-processes across threads introduced thread-local lock contention and system warnings. Setting the estimator thread count to single-threaded mode across all sub-trees eliminated concurrency overhead and stabilized real-time execution.
    \item \textbf{Internal Traffic Pre-Filtering:} Local network adapters regularly exchange operational frames such as IPv6 link-local messages, multicast DNS (mDNS), and address autoconfiguration packets. Because benchmark training datasets consist solely of routable host-to-host communications, evaluating these local infrastructure frames with machine learning models led to false positives (such as mDNS multicasts incorrectly flagged as Brute Force). A pre-prediction filter screens out loopback, link-local, multicast, and broadcast addresses before inference, allowing only routable unicast traffic to reach the classifier.
    \item \textbf{Dashboard Self-Traffic Exclusion:} The web user interface communicates with the FastAPI server over port 8000 using HTTP and WebSockets. To prevent feedback loops where dashboard communications generate captured packets that re-enter the feature extractor, all packets on destination or source port 8000 are automatically bypassed from flow tracking and alerting.
\end{enumerate}

\chapter{Conclusions}

This project presented the design, implementation, and empirical evaluation of the Network Intrusion Detection and Alert System (NIDAS), an end-to-end framework capable of capturing, analyzing, and detecting network-level intrusions in real time. Rather than relying solely on sanitized benchmark performance, the system was validated across both offline benchmarks and live network captures, providing critical engineering insights into the realities of deploying machine learning in operational cybersecurity environments.

\section{Implementation of the Real-Time IDS Pipeline}

NIDAS successfully established a complete, standalone network monitoring pipeline that spans all layers from wire-level packet capture to automated incident notification:
\begin{itemize}[leftmargin=*]
    \item \textbf{Autonomous Flow Generation:} A custom, lightweight Python reimplementation of CICFlowMeter was developed to perform real-time packet sniffing, bidirectional flow tracking, and dynamic computation of 40 flow-level features, bypassing the latency and external dependencies of legacy Java utilities.
    \item \textbf{Ensemble Classification Engine:} A soft-voting ensemble combining Random Forest and XGBoost was trained on the combined CIC-IDS2017 and CSE-CIC-IDS2018 benchmark corpus ($1,799,905$ flows). By uniting the variance-reduction strengths of bagging with the gradient-guided optimization of boosting, the ensemble achieved an offline test accuracy of 99.94\% and a macro-averaged F1-score of 0.9994 across five distinct traffic categories: Normal Traffic, DoS, DDoS, Brute Force, and Port Scan.
    \item \textbf{Operational Telemetry and Alerting:} An automated threat-mapping engine parses ensemble confidence vectors, assigns attack severity levels (Critical, High, Medium), logs persistent incident telemetry to alert\_log.csv, and renders real-time color-coded alerts on both the terminal interface and the full-stack web dashboard.
\end{itemize}

\section{Pipeline Integrity and Training Inference Parity}

A critical empirical lesson uncovered during practical deployment was the strict necessity of end-to-end transformation symmetry between offline training and live inference. In early deployment iterations, a feature transformation discrepancy was identified where discriminative feature weighting ($3.0\times$ for high-importance flow dynamics and $2.0\times$ for medium-importance attributes) was applied during estimator training but omitted in the live inference preprocessing step. 

This discrepancy caused significant confidence skew on boundary attack signatures; specifically, probe and port-scanning vectors exhibited severely degraded classification confidence (collapsing to borderline probabilities of $\sim 4\%$). Rectifying this pipeline bug by ensuring exact symmetry in RobustScaler standardization and weight multiplication immediately restored high-confidence detection ($75\%\text - 96\%$) across live network flows. This underscored that high theoretical model accuracy remains fragile unless absolute parity is enforced between training-time and runtime feature engineering pipelines.

\section{Domain Generalization and Continuous Adaptation}

Evaluating the trained model on live network environments revealed a pronounced generalization gap between static academic benchmarks and modern operational attack tools:
\begin{itemize}[leftmargin=*]
    \item \textbf{TCP Stack and Tool Evolution:} Benchmark datasets recorded in simulated testbed environments capture tool behaviors and operating system TCP stacks specific to their recording era. When modern attack utilities (such as Go-based HTTP flooding scripts or updated Hydra brute-force engines) are executed against contemporary operating systems, deviations in TCP window negotiation, inter-arrival timing, and header lengths cause pure benchmark-trained models to struggle.
    \item \textbf{Syntactic Artifacts vs.\ Behavioral Signatures:} In real-time testing, the baseline model initially exhibited confusion between scanning probes and brute-force attempts because fixed tool payloads (such as Hydra's 56-byte FTP commands versus Nmap's 52-byte probe packets) occupied adjacent feature spaces. By capturing local traffic profiles, applying targeted labeling, and retraining the ensemble on localized behavioral patterns, the model successfully transitioned from memorizing tool-specific payload artifacts to recognizing generalized behavioral signatures (flow duration patterns, packet burst rates, and connection symmetries). This demonstrated that continuous learning and localized retraining loops are indispensable for real-world intrusion detection systems.
\end{itemize}

\section{Critical Analysis of Operational Limitations}

While the ensemble attained exceptional performance on the curated test set (surpassing 99.9\% accuracy with an FPR of 0.021\% on benign traffic), real-world deployment exposed critical, predictable edge cases inherent to flow-based tabular architectures:
\begin{itemize}[leftmargin=*]
    \item \textbf{The Single-Packet / Zero-Duration Trap (UDP Noise):} The 40 flow-level tabular features do not encode transport-layer protocol semantics (TCP versus UDP). Consequently, legitimate single-packet UDP interactions (such as Network Time Protocol (NTP) clock synchronizations characterized by 1 forward packet, 0 backward packets, and 0 duration) produce flow vectors statistically indistinguishable from single-probe reconnaissance scans. This occasionally triggered false-positive Port Scan alerts on benign background NTP traffic, demonstrating that purely statistical flow models require complementary protocol-aware whitelisting or cross-flow correlation.
    \item \textbf{The Temporal Trap (Slow Benign Transactions):} Tree-based models heavily exploit Flow Duration to isolate sustained denial-of-service flooding. However, benign connections with long idle delays or slow server response times (such as slow HTTP/HTTPS transactions spanning 40 to 60 seconds with minimal packet volume) can mimic the temporal profile of low-and-slow DoS attacks (e.g., Slowloris or Hulk). This led to occasional borderline DoS false positives on sluggish web traffic, highlighting that models can become biased toward temporal duration over volumetric packet density.
    \item \textbf{Payload and Encryption Vulnerabilities:} While tabular models reliably identify cleartext protocol artifacts (such as predictable payload distributions in FTP brute-force attempts), identical credential attacks transported across encrypted channels (such as SSH) yield altered packet distributions and encrypted payloads that evade artifact-dependent decision trees.
\end{itemize}

\section{Concluding Remarks}

The ultimate takeaway of the NIDAS project is that benchmark test accuracy, while a vital developmental baseline, represents only a laboratory metric. The true measure of an operational intrusion detection system lies in identifying its operational breaking points under live conditions and understanding the root causes of misclassifications. Flow-level machine learning provides an exceptionally fast, high-throughput mechanism for intercepting volumetric floods and high-intensity exploits. However, achieving production-grade resilience demands a hybrid architecture that augments statistical tabular ensembles with protocol-level heuristic filters, multi-flow connection tracking, and continuous localized adaptation.

\chapter{Future Work}

While the NIDAS implementation establishes a complete and validated operational framework, several promising directions are identified to advance the system toward enterprise-scale cybersecurity deployment:

\section{Continual Learning and Adaptive Concept Drift Mitigation}

A persistent challenge in production intrusion detection is concept drift, where network traffic distributions evolve dynamically due to new software deployments, operating system updates, and evolving adversary tactics. In the current architecture, model retraining is conducted offline using curated historical partitions. Future iterations should incorporate streaming continual learning mechanisms, such as Hoeffding Adaptive Trees and experience-replay buffers, allowing the base estimators to assimilate incremental updates from validated live traffic without suffering from catastrophic forgetting. Furthermore, integrating statistical divergence monitors---such as the Population Stability Index (PSI) and Wasserstein distance computed over rolling windows of flow inter-arrival times---would enable automated triggering of localized retraining routines whenever significant distribution shifts are detected.

\section{Explainable AI (XAI) and Real-Time SHAP Attributions}

In operational Security Operations Centers (SOCs), automated alerts must be accompanied by transparent rationale to enable rapid triage and incident response. While the current dashboard surfaces calibrated class probabilities, integrating real-time Explainable AI (XAI) techniques represents a crucial enhancement. Implementing an optimized TreeSHAP (SHapley Additive exPlanations) engine within the inference pipeline would compute exact feature contribution vectors for every flagged connection. For instance, when a flow is classified as DoS, the interface could present an immediate local attribution waterfall chart indicating that elevated Flow Duration and extreme Bwd Packet Length Std contributed $+0.42$ and $+0.35$ respectively toward the malicious score. Optimizing TreeSHAP tree traversal through path memoization will ensure that explanatory attribution adds less than 1.5 milliseconds of latency to the alerting dispatch.

\section{Hardware Acceleration and Kernel-Level Packet Inspection}

The current Python-based CICFlowMeter operates in user space via standard network sockets, which delivers dependable throughput for monitoring standard local subnets but introduces operating system context-switching overhead under line-rate gigabit flooding. Future work will investigate offloading flow extraction directly into the Linux operating system kernel using eBPF (Extended Berkeley Packet Filter) and XDP (eXpress Data Path). By performing packet hashing, timestamping, and counter accumulation within the driver layer before packets reach the OS networking stack, throughput can scale toward 10 Gbps and 100 Gbps enterprise backbones. Concurrently, converting the serialized ensemble into optimized Open Neural Network Exchange (ONNX) or TensorRT binaries will allow parallelized tree evaluation on dedicated edge inference accelerators.

\section{Hybrid Unsupervised Zero-Day Threat Interception}

The proposed ensemble excels at multi-class classification across known attack families (achieving 99.94\% test accuracy). However, purely supervised learning remains inherently constrained by the scope of historical training labels. To protect against novel zero-day exploits and sophisticated advanced persistent threats (APTs), future iterations will couple the supervised soft-voting ensemble with an unsupervised anomaly detection branch, such as a deep convolutional Autoencoder or an Isolation Forest fitted exclusively on legitimate baseline traffic. When incoming flows exhibit low supervised confidence alongside high autoencoder reconstruction error, the system will flag the traffic as an uncharacterized zero-day anomaly, quarantining the connection and routing telemetry to human security analysts for forensic payload analysis.

\subsection{Operational Analysis of Real Incident Telemetry}

The telemetry records documented in Table~\ref{tab:sample_telemetry} demonstrate the operational behavior of the detection pipeline across benign sessions, volumetric rate anomalies, and multi-flow reconnaissance activities:

\begin{enumerate}
    \item \textbf{Benign Baseline Validation:} Standard application communications (such as DNS resolution on port 53, HTTP transactions on port 80, and encrypted HTTPS sessions on port 443) maintain balanced bidirectional packet flows with regular TCP control flag sequences (PSH, ACK, FIN) and proportional byte transfer volumes. The ensemble assigns confidence values exceeding 99\% to these sessions, validating that routine enterprise workstation traffic passes through without generating spurious security alarms.
    \item \textbf{Infrastructure Noise Suppression:} Operational background frames such as Link-Local Multicast Name Resolution (LLMNR on port 5355) and Multicast DNS (mDNS on port 5353) exchange small local broadcast packets. Because these frames are captured on live network interfaces but never appear in external network datasets, evaluating them directly with machine learning models frequently resulted in false-positive classifications. The system's pre-prediction filter screens these non-routable local addresses, logging the flows for forensic tracking while bypassing the prediction engine.
    \item \textbf{Directional Asymmetry in Denial of Service:} Both the sustained and rapid-burst DoS anomalies captured on port 68 exhibit severe directional asymmetry, with four forward packets totaling 1,312 bytes and zero backward response. In the rapid-burst scenario, the flow duration collapsed to 17.3 milliseconds, producing an intense delivery rate of 231.6 packets per second. This sharp statistical deviation immediately triggers a Critical severity classification, providing operators with instantaneous alerts during volumetric resource exhaustion attacks.
    \item \textbf{Cross-Flow Correlation and Alert Deduplication:} Because individual port scan probes often resemble benign connection attempts when evaluated in isolation, single-flow machine learning models can overlook distributed reconnaissance. The sliding-window detector tracks unique destination ports per source IP over a 60-second horizon. When host 192.168.1.42 crossed the 15-port threshold by probing 18 distinct ports, the system elevated the incident to a Medium-severity Port Scan. Subsequent probes from the same source during the active episode were recorded in the audit CSV while suppressing duplicate alert popups, mitigating operator notification fatigue.
\end{enumerate}
